# Simplify Theme · UI 重整设计与验收契约

目标是一个可长期使用的 DSH 对话工作台。沿用用户参考图的中性蓝灰表面、分层侧栏和委派图，不把营销图里的虚构导航或任务清单注入真实会话。对话是主区域；输入是主操作；用量与子代理是从属信息。

## 布局与密度

- 保留宿主侧栏宽度、导航、消息列宽度和分屏机制；主题不重新实现应用壳。
- 顶栏沿用宿主结构，只有真正的对话头部需要表面处理，不匹配所有含 `_header` 的类。
- 输入区的附件、原生权限、插件模型/思考等级、其他插件控件、发送/停止各保留一份。只在替代模型座实际存在时隐藏原生 ModelSelect，不能隐藏整个 standardControls，也不能隐藏其他 menu 按钮。
- 输入卡保持稳定的 token 表面；有数据时 HUD 在 dock 中轴居中、按内容收缩，不强制与输入卡共享边缘。统计关闭或无数据时恢复宿主原生统计与独立圆角。
- HUD 是居中的单行内容胶囊，不用 flex-basis 数学排布，也不强制拉满输入卡。宽度由真实指标内容决定，最大不超过 dock；存在子代理且容器 ≥880px 时可附显子代理计数，<880px 先隐藏子代理计数，<760px 隐藏会话规模/TPS，<640px 再隐藏缓存命中，340px 仍保持单行且高度 30–44px。点击后在浮层查看完整指标。
- HUD 展示真实会话轮/步、上下文占用、端到端平均 TPS、缓存命中、耗时尾行（以及宽屏 ≥880px 时的子代理计数）。累计 TPS 不标为“实时”，无数据不填 0 冒充测量，缓存数字不重复前缀。上下文容量只接受当前 projected/pressure/breakdown，不用历史累计 Token 冒充；本轮耗时与模型累计耗时使用不同标签。
- 详情弹层有可访问名称、Escape/外点关闭，窄屏/短视口内可滚动。不能因 blur/transform 祖先而定位出视口。
- 委派摘要默认折叠。展开后保留顶部编排节点与弧线；根据实际容器宽度四/二/一列卡片。标题、模型、状态、实际步骤数、打开/停止操作清晰分层；不生成未经证实的“已完成清单”。主节点状态必须反映子节点聚合结果。

## 配色（单一 Token 来源）

- 画布 `#0b1420`；侧栏 `#0a121d`；一级面 `#101c2b`；浮层面 `#152337`。
- 主文字 `#e9effa`；次文字 `#a6b5cd`；说明 `#8497b3`（小字避免过暗）。
- 主强调 `#7aaaf0`；成功标签 `#57d6a0`；警戒标签 `#ffd18a`；失败标签 `#ff9b9b`。职责色只用于委派图图标与细边。
- 保留冷色边界和短阴影，减少多个大面积外发光；只有真正的菜单/浮层允许有限模糊，输入卡、委派卡和 HUD 使用稳定不透明 token 表面。深浅主题各自成立。
- `themeOverrides` 控制全局皮肤，关闭后必须完整恢复宿主全局颜色和布局表面。Token 由 `ctx.theme.overrideTokens` 负责；插件变量只作为 token 别名，不建立第二套硬编码颜色事实源。
- 不使用全局 `[class*='_root']`、`[class*='_header']`、`[class*='_frame']` 或全局通配菜单隐藏规则；必要 CSS module 后缀匹配要受确定结构约束并有防误伤测试。

## 字体与字号

使用宿主系统无衬线字体；数字使用 tabular-nums，不引入网络字体。正文14/22px；控件13/20px、高28px；指标标签11/16px；HUD读数13/20px；单位11/16px；图谱标题14/20px；编排节点标题16/22px；状态12/18px。缩窄时改布局而非缩小文字。

## 验收矩阵

1. 新会话/现有会话、明暗主题、themeOverrides开/关、dockStats开/关/无投影。
2. 独立组件预览与宿主结构契约测试分开命名；不能把合成壳截图描述成真实应用截图。
3. 使用宿主相同的 composer/dock slot wrapper、原生模型/权限 DOM 和布局 CSS 验证 1040/720/600/390px 内容宽度、开右侧分屏、短高度。
4. 确认只有原生 ModelSelect 隐藏；原生权限、input.right 的图像插件按钮、其他 menu 按钮可见；禁用模型替换后原生模型恢复。
5. HUD 几何断言单行高度、内容宽度与中轴位置，确保不越过 dock/卡片边界；开关关闭恢复原生圆角；详情弹层全部位于视口并可访问。
6. 委派 running/done/failed/denied、长中英文标题、1/4/8节点、折叠/展开/卸载，真实步数和状态一致。
7. 运行类型检查、单元测试、浏览器回归和构建，审查 final diff。真实桌面截图只有工具实际采集成功且验证构建版本后才可作为证据；无法采集必须保留未完成项。
